# Slacker

Slacker 提供 TLS 1.3/TCP 和 UDP 两种传输。两者都支持本地 HTTP、SOCKS5 TCP 以及 SOCKS5 UDP 转发。

## Debian 一键安装或升级

下载 Release 附件 [cm.sh](https://github.com/336888/Slacker/releases/latest/download/cm.sh)，在文件所在目录执行：

```bash
sudo bash ./cm.sh --install
```

脚本识别 AMD64 或 ARM64，下载相应的完整包，校验归档和文件，再安装主程序、REALITY 组件和 `cm` 管理菜单。在线安装需要访问 GitHub。私有仓库首次下载脚本需登录 GitHub。此公开仓库可匿名下载。如果当前账号已登录 GitHub CLI，脚本也会使用它的凭据。非交互安装支持 `GH_TOKEN` 或 `GITHUB_TOKEN`，使用 sudo 时需让安装进程取得该环境变量。

完成本次更新后，后续直接运行 `sudo cm --install`，或在 `sudo cm` 菜单选 **1**。升级会短暂重启服务，并检查已启用的入口。脚本沿用已有用户和节点密钥；新版服务验证失败时恢复上个版本。离线安装可解压同版本的 Debian 完整包，从包内运行同一条命令，系统依赖仍通过 apt 安装。

在 `sudo cm` 里选 **5** 查看当前并发流数及上限（512）、因满载被拒的次数、请求头和半关闭连接的超时次数，以及各用户本月的收发流量。流量按服务端本地日历月统计，跨月自动恢复配额。拒绝和超时次数从本次服务启动开始累计。服务端等待完整请求头最多 10 秒。TCP 一侧结束发送后，反向传输连续 2 分钟没有写入进展才回收连接。

## Windows 客户端

Slacker 沿用 ChronoMorph 的节点链接、客户端配置和 Debian 服务目录。Windows 升级时先从托盘退出旧版，将新版 EXE 放在原客户端目录，保留 `client.json`。

- **去广告**管理域名订阅、暂停过滤、查询命中规则和维护放行名单。可直接添加 217heidai 订阅。
- **分流规则**支持本地规则和 blackmatrix7 的 Surge 文本订阅。每行本地规则写作 `DOMAIN-SUFFIX,example.com,DIRECT`。可用动作是 DIRECT、PROXY、REJECT，可用类型是 DOMAIN、DOMAIN-SUFFIX、DOMAIN-KEYWORD、IP-CIDR 和 IP-CIDR6。每行订阅写作 `DIRECT https://…/xxx.list`。本地规则优先，首条命中生效。保存并更新后可测试域名或 IP。更新失败保留已有规则，重启可从缓存载入。
- **进程模式**可以分别创建进程规则与 IP 路由表。填写备注和文件名，输入或扫描 EXE，或选择某个目录。两侧列表分别指定接管与直连，直连例外优先。点击「验证」和「保存模式」，再选中并点击「使用选中模式」。重新开启 TUN 后生效。回环选项处理已接入本地 HTTP/SOCKS 代理的 TCP 请求，Windows 原生本机回环不经过 Wintun。

智能分流按目标域名或 IP 判断。TUN 收到的普通 IP 数据包按可见 IP 判断。全局代理及串联节点继续通过代理转发，拦截规则仍然有效。

## Windows 高级网络设置

打开「设置 → 高级网络设置」，修改后点「保存本页」。监听地址在断开连接时修改。网卡、进程和 DNS 选项在下次开启 TUN 时生效。已有配置继续使用原有监听地址和 DNS 上游。

| 页面 | 可配置行为 |
| --- | --- |
| 常规 | 混合代理端口、允许局域网设备接入、托盘快捷节点数（0–12）、认证探活间隔、连接后多少秒测速（-1 关闭）、STUN 映射查询与界面语言。CM 测完整隧道，TCP 和 ICMP 测本机到物理入口。纯 UDP 节点没有 TCP 测速端口。 |
| 进程模式 | 逐行填写 EXE 文件名，可包含子进程，留空时匹配所有进程。对进入 TUN 的 TCP/UDP 单独选择是否代理，其余流量经物理网卡直连。配置了进程名单而无法识别套接字归属时，关闭该连接。ICMP Echo 可选择本地模拟回复并设置延迟。 |
| WinTUN | 自定义虚拟 IPv4、连续子网掩码和可选网关。直连名单接受 IPv4、IPv6 和 CIDR，对进入 TUN 的流量生效，包括双跳模式。 |
| DNS 分流 | 国内 DNS 匹配 `.cn` 及填写的域名后缀。其余查询走其他 DNS。国内 DNS 留空时全部使用其他 DNS。每组可以配置多个 TCP 上游，按顺序尝试。统一自定义 DNS 覆盖两组。关闭 DNS 接管时，自定义 DNS 用作网卡 DNS，端口为 53。 |

接管 DNS 对进入 TUN 的 TCP/UDP 53 端口生效，应用自带的 DoH 或 DoT 使用普通加密连接。勾选「仅指定进程的 DNS」时，Windows DNS Client 代应用发出的共享查询只能看到服务自身。勾选「DNS 经过 CM 节点」时，解析通过 CM 隧道发出。STUN 检测需手动点击，会向填写的服务器发出一次 UDP 查询。

## Windows 实时连接与节点延迟

启动连接后打开「实时连接」。列表每秒刷新，显示 CM 正在处理的 TCP 连接和 SOCKS5 UDP 会话。可以按进程名、PID、域名、IP、协议或路由标签筛选，并对所选连接查看上下行累计字节和持续时间、复制目标或断开。列表最多显示最近的 200 条匹配项，搜索覆盖全部活动连接。关闭的连接自动移出，列表仅驻留内存。

UDP 按关联会话合计，详情显示最近一次发送的目标。Windows 按本地代理入口识别进程。经内置 TUN 转接的流量显示为「CM 本机转接」，远端设备或无法匹配的连接显示「进程未知」。页面仅显示经过 CM 代理的数据连接。

「我的节点 → 节点延迟测试」按实测往返延迟排序，无应答节点列在末尾。测试保留当前出口。原有「测速优选」仍会切换到最快可用节点。

混合监听端口（默认 `127.0.0.1:1080`）同时接受 HTTP、SOCKS4、SOCKS4a 和 SOCKS5。老软件可选 SOCKS4 使用 IPv4，或选 SOCKS4a 传递目标域名。两者支持 TCP CONNECT，UDP 应用可继续使用 SOCKS5 或 TUN。

## TUN、换网与弱网诊断

Windows 的 TUN 会接管默认 IPv4 流量和公网 IPv6（2000::/3），保留更具体的系统路由，包括本地网络和到实际前置节点的出站路由。「连接日志 → 检查路由与 DNS」显示两个示例地址实际选中的接口、前置和出口的认证应答，并通过本地 DNS 查询 example.com。可以在 TUN 关闭时选择「阻止 TUN 内 IPv6」。此选项拦截交给虚拟网卡的新 IPv6 连接。局域网、更具体的系统路由及自行选择网卡的应用可能有不同路径。

TUN 每 5 秒复查上行路由，网关变化时重新建立传输。自动恢复先验证原链路，连续探活失败后才尝试经过认证的已保存备用节点。TLS 单协议、HTTPS 和 REALITY 出口在自动切换时保留原节点类型。「设置 → 锁定备用类型」可对其他节点也使用该规则。双跳保持所选前置。失效的 TCP 连接和游戏会话需要应用重新连接。

本地 DNS 同时接受 UDP 和 TCP。默认在隧道内顺序尝试 1.1.1.1:53 与 9.9.9.9:53，成功后优先复用可用上游。两者都失败时返回 SERVFAIL。可在 client.json 使用 `"dns_upstreams": ["1.1.1.1:53", "9.9.9.9:53"]` 自定义上游。出口到这些解析器使用普通 DNS/TCP。

「我的节点 → 节点延迟测试 → 60 秒线路质量测试」对当前应用 UDP 通道发送认证探测。空闲阶段约 30 秒，下载阶段最长 30 秒、最多 128 MiB。显示成功样本的 P50、P95、应答间隔和失败次数。下载流量由出口提供，负载测试需 v1.4.6 或以上服务端，旧版仍可测空闲指标。持续时间包含网络应答开销，达到流量上限会提前结束。可手动停止。

## Windows 链式代理与去广告

先导入两个 CM 节点。在「我的节点」选择 B 并点「使用选中节点」，再到左侧「链式代理」选择 A 作为前置，点「保存链路」。连接顺序为本机 → A → B → 目标网站。应用 TCP、应用 UDP 和出口测速都经过 A，B 提供最终出口。前置可以使用已有 CM 传输，出口需要有 TCP 入口（REALITY、HTTPS、TLS 或自动节点）。链式模式下应用目标统一走出口；一个节点不可达会导致连接失败。要换成普通单节点，选「关闭链式代理」并保存。

在左侧「去广告」可点「添加 217heidai 订阅」，或每行输入一个 HTTPS 域名列表地址，点「保存并更新订阅」。客户端接受纯域名、`||域名^` 和 `@@||域名^`；域名规则覆盖子域名，例外优先于订阅拦截。下载成功后规则用于 HTTP、SOCKS5 的域名请求和 TUN 的本地 DNS。首次下载需要联网，以后优先使用本地缓存，每 8 小时刷新。清空订阅列表并保存可关闭。直接连接 IP、应用自带加密 DNS 和同域名视频广告可能不受域名拦截影响。

「去广告 → 域名检查与放行」支持粘贴域名或网页地址。点击「检查」可离线查看当前决定、匹配的域名和订阅序号。点「放行此域名」立即保存，对该域名及子域名生效。删除误加的条目后点击「保存放行名单」。手动配置的本地拦截规则优先于放行名单，放行不改变节点或出口。临时排查网站故障时可在「去广告」点「暂停过滤」，处理完点「恢复过滤」沿用原订阅和缓存。

## Debian 和 Windows 的免证书 REALITY 入口

使用现有 Debian VPS 即可，无需 AWS 账号、自有域名或手动上传证书。安装时自动生成服务端密钥。公网入口接收 TLS 1.3 连接，普通浏览器访问配置的服务器名称时，由指定 HTTPS 站点完成握手并返回网页。节点客户端使用 REALITY 公钥和短 ID，并在加密通道内验证原有用户凭据和服务端指纹。目标网站域名不会改变 VPS 的公网 IP 或网络归属，流量仍可能被识别。

1. 按上面的 Debian 一键安装或升级步骤安装主程序和配套组件。
2. 输入 `sudo cm`，选 **12 → 1**。填入从 VPS 能正常访问、证书覆盖该域名且支持 TLS 1.3 的目标站，例如可尝试 `aws.amazon.com`。填写节点的空闲 TCP 端口，默认 443；目标地址默认用所填域名的 443。主机防火墙与云安全组需要放行节点端口。该模式使用一次外部目标连接来建立新的传输会话，目标不可达时新连接会失败。
3. 选 **4** 获取 `cm+reality://` 链接。Windows 下载单文件 [Slacker-windows-amd64.exe](https://github.com/336888/Slacker/releases/latest/download/Slacker-windows-amd64.exe)。彻底退出旧客户端，打开新版，在「导入节点」粘贴链接并测试。Windows v1.4.2 起也可直接粘贴菜单 4 中带有 `[IPv4 REALITY]` 或 `[IPv6 REALITY]` 的一整行，每次选择一个节点。链接包含用户凭据，请仅交给节点使用者。
4. 用 `sudo chronomorph reality -check` 在 Debian 本机验证普通 HTTPS 的目标站证书、节点身份和隧道应答。外部 Windows 客户端连通后，可以选 **12 → 2** 关闭旧入口；需要恢复并存选 **12 → 3**。菜单重启服务并验证，失败会恢复原配置。

外层握手使用 [XTLS/Xray-core v26.11.9](https://github.com/XTLS/Xray-core/tree/676eaf66f8f05d4d558ee7a74b4736623d3feeb9) 和其锁定的 [REALITY](https://github.com/XTLS/REALITY/tree/4bb46b2afd8b)。内部传输使用 Slacker，节点链接仅适用于支持此入口的 Slacker 客户端。SOCKS5 UDP 数据通过 TCP 承载，线路丢包时会受到 TCP 重传影响。

## 自有域名 HTTPS 网站入口

v1.3.0 的 `cm+https://` 节点使用你自己域名的有效证书。普通浏览器打开网站时，入口将网页请求送到指定的本机 HTTP 网站。浏览器可协商 HTTP/2，无需出示客户端证书。Slacker 客户端通过系统信任链和域名验证证书，再用现有用户密钥对本次 TLS 连接签名，建立 HTTP/1.1 CONNECT 隧道。认证信息无法在另一条 TLS 连接上重用。网站入口沿用服务端用户、流量计数和配额。TCP 和应用 UDP 均走 HTTPS/TCP，丢包时可能等待重传。

1. 准备能直接指向节点的域名、与之匹配的完整证书链和私钥，以及一个本机可访问、准备公开的网站，例如 `http://127.0.0.1:8080`。网站证书的 TLS 连接必须由 Slacker 直接终止。把后台管理页作为源站会将它公开。端口需要可独占，已有服务占用 443 时可先用另一个空闲 TCP 端口测试。
2. 升级 Debian 和 Windows 到 v1.3.0。运行 `sudo cm`，选 **11 → 1**，输入域名、端口、证书链和私钥的绝对路径，以及 HTTP 源站。选 **4** 导出 HTTPS 链接并在 Windows 导入。旧客户端继续使用原节点。域名、证书与源站由你维护；续签证书后重启服务加载新证书，域名不变时原 HTTPS 链接继续有效。
3. 在外部浏览器访问该域名与端口，确认看到自己的网页，并在新版客户端验证连接。然后可选 **11 → 2** 停用本服务旧 TCP 和 UDP 监听。处在并存模式时，同一 IP 上的旧入口仍可访问。需要恢复旧节点时选 **11 → 3**，关闭网站入口选 **11 → 4**。修改运行中的服务会短暂重启；在线验证失败时会恢复先前配置。
4. 在服务器运行 `sudo chronomorph website-check`，可分别检查网站首页和经过认证的隧道。云安全组需要放行网站 TCP 端口。

该模式使用 Go TLS 和你的真实网站。它与 VLESS/REALITY 不互通，域名、IP、握手和流量时序等仍可被观察。现有 `cm://`、`cm+tls://`、`cm+auto://` 的行为见下文。

在 Windows「我的节点」中选中一行，点击「删除选中节点」。删除活动节点会断开连接，可在剩余节点中重新启动。删除只影响这台客户端。UDP 节点超时时，两端升级到 v1.1.2 后可在「连接日志」查看是 Debian 节点未响应，还是节点已响应但目标连接失败。

v1.2.3 客户端支持在节点握手超时时直接断开或切换节点。网页通道等待节点应答期间，游戏和语音仍可独立建立 UDP 转发。此次升级可以沿用 v1.2.2 服务端及现有节点链接。

## 游戏与并发下载

v1.1.1 客户端将 SOCKS5 UDP 游戏和语音放在独立传输连接上。第一次发送 UDP 请求时才建立这条连接。同一节点上的 TCP 下载使用另一条连接。两条连接仍共享用户配额和实际链路带宽。现有 `cm://` 与 `cm+tls://` 节点可以继续使用。先升级 Debian 服务端，再退出并更新 Windows 客户端，可同时获得端口变化、快速重启和并发流控修复。

Slacker 借鉴 Hysteria 2 区分可靠流与应用数据报的思路。当前 UDP 应用数据仍通过 KCP 或 TLS 的可靠传输转发，丢包时本条连接仍可能等待重传。协议细节见 [Hysteria 2 官方规范](https://v2.hysteria.network/docs/developers/Protocol/)。

## 仅 TLS 传输

Windows 设置页可打开「仅 TLS 传输」。现有 `cm+auto://` 和 `cm+tls://` 都可直接使用，旧 `cm://` 节点需从服务端菜单 4 重新导出双协议链接。命令行客户端可在 `client.json` 中设置 `"tls_only": true`。设置只保存在本机，默认关闭，分享链接保留原始端口与证书指纹。当前使用纯 UDP 节点时，请先导入双协议链接，再打开开关。

开启后网页、游戏和节点测速到节点的连接都只用 TLS/TCP。TLS 失败时返回错误，旧 UDP 节点不会参与测速；游戏的应用 UDP 数据仍能通过 SOCKS5 转发。在丢包线路上，游戏延迟可能因 TCP 重传而升高。切换传输会重建当前隧道，并将 TUN 的本地 DNS 转向新的节点。

此开关只控制进入 Slacker 后到节点的传输。目标站点仍能看到出口 IP，网络观察者仍能看到节点 IP、流量大小和时序。系统代理、全局/智能分流与 TUN 的覆盖范围由各自设置决定。

## Debian 服务端证书迁移

v1.2.5 新安装生成的自签名服务端证书以随机序列号作为主题和签发者。已经部署的节点会沿用现有证书和指纹。需要清除旧版 `CN=ChronoMorph` 时，先解压新版离线包并运行 `sudo bash cm.sh`，选 1 升级，再选 10 迁移证书。确认后将有一次短暂的服务重启。菜单会备份原证书和私钥，并在运行中的 TLS 服务验证失败时恢复它们。已停止的服务会在下次启动时使用新证书。

迁移成功后，选 4 导出链接，让每台使用 TLS 的客户端重新导入。原有用户密钥、配额和端口沿用，无需重装客户端。在服务端运行 `sudo chronomorph tls-identity -subject` 可检查磁盘上的证书主题，新格式为 `SERIALNUMBER=…`。这项改动移除证书中的项目名称，节点 IP、证书指纹和其他流量特征仍可观察。

## TLS 握手与升级

v1.2.6 服务端停止选择旧的项目专用 ALPN，客户端证书也使用每次签发的随机序列号。先升级 Debian，再更新 Windows。v1.2.2–v1.2.5 客户端连接新版服务端仍可以使用大窗口。新版客户端连接 v1.2.5 或更早服务端时会使用兼容模式，吞吐可能降低。两端升级后恢复大窗口，已有证书指纹和节点链接可沿用。若服务端仍使用更早的具名证书，请按上节迁移。

旧式跳频 UDP 客户端会在首包或换端口时发送一个 STUN 请求。v1.2.6 客户端直接发送已认证数据，服务端丢弃旧请求并继续接收后续数据。固定端口与跳频模式均可用。UDP 报文头、TLS 握手行为、流量大小和时序仍然可观察。

## 测量吞吐

Windows 的「测速」显示往返延迟。要复现吞吐对比，可在 Linux 对编译好的客户端和服务端二进制运行以下命令。脚本在本地启动服务端、客户端和测试目标，按方向传输 8 MiB 数据三次并校验内容，输出应用层 Mbps。用 `--transport udp` 测固定端口 UDP，或用 `--transport auto` 测双协议节点实际选中的路径。

```sh
python3 tests/throughput.py ./slacker-linux-amd64 --transport tcp --rtt 200 --mbps 100
```

## 双协议节点

1. 下载本版 Debian 离线包，解压后进入同名目录，运行 `sudo bash cm.sh`，选 `1` 升级。安装脚本为现有 UDP 监听地址启用同端口的 TLS/TCP；已配置的 TLS 端口会沿用。如果 TCP 端口被占用，选 `9` 设置其他空闲端口。
2. 按菜单实际显示的端口放行云安全组和主机防火墙。新装默认 TCP 40000、UDP 40000。旧 `cm://` 链接仍需原来的 UDP 转发端口范围。
3. 选 `4`，复制对应公网 IP 的 `cm+auto://` 链接。Windows 从托盘彻底退出旧程序，换新版 EXE，点「导入节点」粘贴链接。旧 UDP 链接缺少 TCP 端口和证书指纹，需要导入新链接才能自动切换。
4. 网页连接优先 TLS/TCP，SOCKS5 UDP 游戏或语音优先固定端口 UDP。首选通道在 250 毫秒内未完成认证时，客户端同时尝试另一条通道，并使用先认证成功的一条。应用数据只发往选中的通道。中断后新建连接可以换路，已中断的下载和游戏会话需由应用重连。「连接日志」显示两类流量各自选中的传输。
5. 两端的 TCP/UDP 端口可不同；都保存在同一条链接里。命令行客户端可配置 `server_ip`、`master_key`、`tls_port`、`tls_pin` 和 `udp_port`。已有 `cm+tls://` 固定使用 TLS/TCP。

## 快速开始

1. **推送到 GitHub 自动编译**：在 Actions 的 Release Slacker 页面手动指定版本，或推送标签 `git tag v1.4.1 && git push origin v1.4.1`，在 Releases 页面下载四端产物。
2. **Debian 服务端部署**：按菜单放行双协议节点的 TCP 和 UDP 端口，从 Release 下载 `slacker-debian-amd64.tar.gz`（x86_64）或 `slacker-debian-arm64.tar.gz`（aarch64）。解压并进入同名目录，运行 `sudo bash cm.sh`，选 1 安装或升级。离线包含服务端程序，首次安装系统依赖仍使用 apt，后续输入 `cm` 唤出管理菜单。
3. **Windows 客户端**：双击单文件客户端打开原生桌面窗口。REALITY 已编译进主程序。在「导入节点」中粘贴分享链接。最小化或关闭窗口会收起到托盘，再次双击 EXE 或选择托盘「打开主窗口」即可恢复。退出请选择托盘「彻底退出」。启用 TUN 时，以管理员身份运行客户端，先连接节点，再在「设置」点击「开启 TUN」。首次启用会将 EXE 内置的官方签名 Wintun 0.14.1 安装到程序文件目录，下次开启时校验并复用。第三方许可可运行 `Slacker-windows-amd64.exe licenses` 查看。
4. **Android 客户端**：提供 ARM64 命令行程序。在可执行目录准备好 `client.json` 后，运行 `chmod +x slacker_android_arm64 && ./slacker_android_arm64 client -c client.json`，默认监听 `127.0.0.1:1080`，接入 Mihomo/Clash 的 `socks5` 节点（并在规则顶部放行 VPS IP 直连）。

Windows 客户端直接使用 Win32 桌面窗口。导入后启动本地代理，点击「测速」验证服务端应答。升级 Windows 客户端前，请先退出旧进程。每台客户端请使用独立的服务端用户密钥。
